# 暗所で武器だけ明るい問題の調査と試験修正

ユーザーは前回の統合3,996三角形版を導入し「成功した」と報告した。2026-10-11 17:33:54の実機スクリーンショットでは、周囲や手袋に比べて鎖・柄が明るく見える。この報告を受け、照明設定だけの小さな試験修正を行う。

## 確認した事実

- ゲームに配置されたNIFのSHA256は`a2f5a40473884201c1eac9257f12d81a973d918d84d403ef8b914af36bc8d2c9`で、前回配布のNIFと一致した。
- 全31表示材質の発光色は黒、Glow Mapは未使用。白い発光色が直接設定されていたわけではない。
- ユーザーのSkyrim VRのBSAから鉄・鋼メイスを読み取り、固定niflyで材質を比較した。標準武器は`Own Emit`と`EnvMap Light Fade`を持つが、CMSの表示材質には両方が欠けていた。
- 木と革は環境マッピングを使わない。金属の環境反射だけでは柄の明るさまで説明できない。

## 原因候補と小さな修正

標準武器と異なる発光色の扱い、および暗所で環境反射を弱める設定の欠落が、明るさの残る原因候補となる。NIF形式の一次資料はOwn Emitを自身の発光色の指定として説明しているが、環境色との正確な相互作用には未確定の記述もある。実際のゲームでの改善はユーザーによる比較が必要で、原因を完全に確定したとは扱わない。

| 表示材質の項目 | 前回 | 今回 |
| --- | --- | --- |
| Own Emit | 無効 | 有効、自身の発光色は黒 |
| Emissive RGB | 0, 0, 0 | 0, 0, 0 |
| Emissive Multiple | 1 | 0 |
| EnvMap Light Fade | 無効 | 有効 |
| 光沢・反射強度・環境反射倍率 | 既存値 | バイト同一 |
| 全21 DDS | 既存値 | バイト同一 |

Own Emitを有効にすることと、明るい発光を加えることは同義ではない。今回は黒・強度0を明示する。木、革、黒鉄を一律に暗く塗り直す操作は行わず、照明への反応を修正する。

## 保存と再生成の保護

`nif_material_contract.py`は入力NIFの全体SHA256とSSE/VRのブロック配置を検証し、31表示シェーダー内のflags1、flags2、emissiveMultipleだけを書き換える。NIF全体の124バイトが変わる。ヘッダー、フッター、頂点、面、UV、法線、接線、ノード、衝突、血、テクスチャ参照などの非対象バイトが変化したら停止する。異なるモデルや二重適用も拒否する。

`inspect_nif_materials`は固定niflyで変更前後を独立に読み取る。2血用形状は照明材質も含めて完全同一。形状・寸法・19節・血込み3,996三角形を維持する。DLL、ESP、音声、21DDSも前回統合版と同一。

Windows CIは保存済みBlender/CMSの安全確認付き経路で前回のNIFを再生成し、元audit6の再現を確認してから、この材質だけの修正を適用する。元モデル生成スクリプトを実行してBlender編集を上書きしない。最終成果物は本体を含む`ChainMorningstarVR-1.0.0-audit6-unified-lighting-test.zip`。

この仕上げブランチでは、旧モデルと元テクスチャを再生成する2つのCIジョブを明示的にスキップする。保存済みの編集入力を読む統合テストのCIだけを外観成果物の生成経路とする。mainや他のブランチの既存ジョブにはこのブランチ条件は適用しない。

## 導入と比較

ゲームを終了し、前回の統合版と旧audit6本体・外観テストをすべて無効化する。今回の統合ZIPだけを有効にしてESPを有効化し、配置して再起動する。前提MODは維持する。既に所持する武器にも反映される。

同じ暗い場所、視線、持ち方、光源でユーザー画像と比較する。明るい屋外や松明の近くでも木目・革・黒鉄が自然に見えるか確認する。こちらから実機の同一視点・照明を操作できていないため、ゲーム内の変更後画像を生成・加工して確認済みとはしない。BlenderのPrincipled変更をゲームへの反映として扱わない。

戻す場合は今回版を無効化し、前回の統合3996版を再有効化して配置・再起動する。両統合版を同時に有効化しない。今回版の照明、掴み、血、摩擦、装備解除、音、FPS、xEditは実機未確認。mainへの統合や正式公開は行わない。
